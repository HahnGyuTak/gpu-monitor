# 디자인 점검 — 0.7.0

판단 기준은 화면에서 확인할 수 있는 읽기 순서, 정보 밀도, 컨트롤과 창의 실제 동작입니다. 색상이나 모서리 모양만으로 문제를 판단하지 않았습니다.

## 관찰한 문제와 수정

| 관찰 | 작업에 미치는 영향 | 수정 |
| --- | --- | --- |
| 520×700 화면에서 4개 GPU가 큰 2×2 패널을 차지하고 제목·설명이 반복됨 | 학습 진행률·ETA와 다음 서버를 보려면 먼저 스크롤해야 함 | GPU를 정렬된 행으로 바꾸고 제목·설명을 줄임. 같은 예시 데이터에서 진행률·ETA와 두 번째 서버가 함께 보임 |

| 작업의 고정·감시가 핀·벨 아이콘만으로 표현됨 | 아이콘의 뜻과 현재 선택 상태를 해석해야 함 | ‘고정’·‘감시’ 체크박스와 ‘로그’ 텍스트 버튼으로 표시 |

| 독립 창의 크기가 고정되어 있고 확대 동작이 비활성화됨 | 서버가 많거나 이름이 길어도 표시 영역을 조절할 수 없음 | 크기 조절·확대·최소화, 창 크기 저장, 다시 열기 및 표준 윈도우 메뉴 제공 |
| 서버 카드 안의 GPU·작업이 반복된 상자와 재질로 나뉨 | 하나의 서버 정보를 읽는 동안 경계가 반복됨 | 서버 단위 컨테이너는 유지하고 내부를 행·구분선으로 연결. 고정 작업에만 선택 배경 사용 |
| 8개 GPU 검증에서 `100%`의 `%`가 다음 줄로 내려감 | 같은 열의 숫자 정렬과 행 높이가 달라짐 | 세 자리 백분율을 위한 폭을 확보하고 한 줄 표시로 고정 |
| 네이티브 글래스 버튼 전환 중 강조색 배경과 같은 색 아이콘이 겹침 | 활성 창에서 상단 아이콘의 대비가 낮아짐 | 일반 글래스 버튼 표면을 중립색으로 유지하고 내부 아이콘에만 선택 색상 적용 |

## 유지한 판단 정보

GPU 사용률·VRAM·온도, 서버 연결 상태와 갱신 시각, 학습 단계·진행률·ETA, GPU–pane 매핑의 불확실성, 오류·종료 상태를 유지했습니다. 접힘·선택·비활성·오류는 색 이외에 화살표, 체크 표시, 텍스트와 시스템 컨트롤 상태로도 구분합니다.

글래스는 상단 및 보조창의 조작 버튼에 적용합니다. 콘텐츠와 설정은 시스템 표면을 사용합니다. 시스템 글꼴과 SF Symbols를 사용하며 폰트를 추가하지 않았습니다. 메뉴바 아이콘 렌더링과 기존 모양·색상 선택은 바꾸지 않았습니다.

## 검증

- 합성 데이터로 대시보드, 설정, 서버 추가, 로그, 빈 상태와 연결 오류를 라이트·다크 모드에서 렌더링해 확인했습니다.
- 4개/8개 GPU, 한영 혼합의 긴 서버 이름, 100%·80 GiB 수치, 기본 520×700·최소 520×420·760×700 창을 확인했습니다. 좁은 창에서는 이름을 줄이고 수치 열과 조작을 유지하며 콘텐츠는 스크롤됩니다.
- 실행 앱에서 설정 이동, 선택 상태, 서버 추가의 기본 포커스와 Docker 입력 포커스, Escape 닫기, 로그 줄바꿈 전환, 네이티브 확대, ⌘W 닫기·⌘0 다시 열기를 확인했습니다. 입력 검증과 원격 삭제 방어는 기존 동작을 유지합니다.
- Python 37개와 Swift 24개, 총 61개 검사를 통과했습니다. GPU 아이콘 배치·설정 보존, 필터·정렬, 동시/개별 갱신, 삭제 전 재검사, 학습 이벤트 판정을 포함합니다.
- Xcode의 네이티브 글래스 빌드와 구형 Swift의 호환 컨트롤 컴파일을 확인했습니다. CI에서는 macOS 14와 26에서 테스트와 앱 빌드를 실행합니다.

투명도·동작 줄이기는 네이티브 컨트롤과 공통 코드에서 대응합니다. 대비 증가 시 서버 윤곽을 강화합니다. 이번 점검에서 시스템 접근성 설정 자체를 바꾸거나 실제 원격 작업을 종료·삭제하지 않았습니다. 모든 macOS 버전에서 수동 실행한 것으로 해석해서는 안 됩니다.
